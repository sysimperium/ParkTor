## Ao configurar a chave PIX nopainel root, percebi que só tema informação da chave PIX, esse não é o padrão do bancop central, para configurar ou gerar um QR Code Pix no padrão do Banco Central (BR Code), o desenvolvedor deve seguir as especificações do Manual de Padrões para Iniciação do Pix, que utiliza o padrão global EMV para pagamentos.Abaixo estão os passos e os pilares técnicos de como o desenvolvedor deve criar essa solução.1. Entendendo o Padrão do Banco Central (BR Code)O padrão do Banco Central para QR Codes e "Copia e Cola" é chamado de BR Code. Trata-se de uma string de texto codificada no formato TLV (Tag-Length-Value). As principais informações que o desenvolvedor precisa inserir na configuração são:Payload Format Indicator (ID 00): Versão do padrão (geralmente fixo em 01).Point of Initiation Method (ID 01): Indica se o QR é estático (sem valor obrigatório, ID 11) ou dinâmico (ID 12).Merchant Account Information (ID 26): Identifica a instituição financeira e a chave Pix cadastrada no DICT.Merchant Category Code - MCC (ID 52): Código da categoria do recebedor.Transaction Currency (ID 53): Código da moeda (BRL é 986).Transaction Amount (ID 54): Valor da transação (opcional, configurável para o usuário digitar depois).Country Code (ID 58): Código do país (Brasil é BR).Global Unique Identifier (ID 00 dentro de 26): Define o arranjo do Pix (br.gov.bcb.pix).Transaction Identification - TXID (ID 05 dentro de 62): Código único que o recebedor cria para identificar a cobrança e facilitar a conciliação.2. O que o Desenvolvedor deve criar no App?Dependendo do objetivo do aplicativo, o desenvolvedor atuará em duas frentes distintas:Cenário A: O App é do Recebedor (Geração de QR Code / Link)Se o app precisa gerar uma cobrança (para o usuário receber dinheiro de terceiros):Interface de Entrada: O app deve ter um formulário onde o recebedor insere o valor e uma descrição.Geração do Payload: O sistema deve concatenar os dados no formato BR Code e gerar um CRC16 (código de redundância cíclica) para validar a integridade dos dados.Cópia e Cola: Converter esse payload TLV em uma string alfanumérica e disponibilizar o botão "Copiar e Colar".QR Code: Utilizar uma biblioteca geradora de QR Code para converter a string em imagem.Para tips on how to get the seasoning and consistency just right:1mGerando QR-Code para a realização de PIXProjeto Inclusão DigitalYouTube• 30 de ago. de 2024Cenário B: O App é do Pagador (Leitura e Pagamento)Se o app precisa ler o código de outra pessoa e iniciar um pagamento:Leitor de Câmera e Área de Transferência: O app deve escanear um QR Code ou permitir que o usuário cole o código "Copia e Cola" gerado pelo recebedor.Validação: O software deve decodificar a string TLV, extrair os dados do recebedor, verificar o CRC16 e exibir as informações de quem vai receber na tela.Iniciação via API: Através da API do seu PSP (Provedor de Serviços de Pagamento - o seu banco), enviar os dados para o Banco Central efetivar a transferência.3. Utilizando Bibliotecas ProntasPara não ter que criar a montagem TLV e a criptografia do zero, o desenvolvedor pode utilizar bibliotecas de código aberto desenvolvidas pela comunidade.Existem pacotes prontos em praticamente todas as linguagens, bastando pesquisar por "Pix Payload BR Code" no GitHub ou npm. Eles fazem todo o trabalho de agrupar as tags e calcular o CRC16 automaticamente.4. Usando APIs do BancoSe o aplicativo for realizar cobranças automatizadas e conciliação em tempo real, ele precisará se comunicar diretamente com o banco. O desenvolvedor deve:Acessar o portal do desenvolvedor da instituição financeira (ex: Portal Developers BB do Banco do Brasil ou a API Pix - OpenPix Developers).Registrar a aplicação e obter credenciais de autenticação OAuth2 e certificados digitais mTLS.Utilizar os endpoints fornecidos pelo banco para criar cobranças dinâmicas e configurar webhooks para receber notificações de pagamento instantaneamente.
